# 测试计划

## 1. 测试层级

| 层级 | 目的 | 运行方式 |
| --- | --- | --- |
| 单元 | 发现器、哈希、要求解析、Schema、门禁。 | Python `unittest`。 |
| 集成 | LaTeX、Markdown、PDF、图片目录生成完整运行账本。 | 临时目录 fixture。 |
| 调度 | 验证模型锁定、并发限制、重试和 fail-closed。 | 纯模拟调度账本。 |
| 视觉回归 | 检查每类公开缺陷均被准确表达和登记。 | fixture 清单与预期发现。 |
| Luna 烟雾 | 真实子代理检查正确与错误图例。 | 手工触发，结果归档。 |
| 文档 QA | README 图片、链接、安装示例与渲染可读性。 | 静态检查加人工视觉复核。 |

## 2. 必测场景

| ID | 场景 | 预期 |
| --- | --- | --- |
| T-01 | Markdown 中两次引用同一图片。 | 产生两个独立逻辑图位。 |
| T-02 | LaTeX 图环境含图注。 | 图位包含图注与源定位。 |
| T-03 | PDF 有多页图像对象。 | 页面与图位可对应，页面渲染存在。 |
| T-04 | 图片目录含 PNG、SVG 与非图像文件。 | 仅产生支持的图像图位。 |
| T-05 | 缺失 `pdftoppm` 或渲染失败。 | 明确限制，整体不得 `PASS`。 |
| T-06 | 用户要求图注必须纳入图。 | 要求进入任务与账本。 |
| T-07 | 用户要求原图另配独立汉化图。 | 角色和配对要求可记录。 |
| T-08 | 所有任务完成且无阻断发现。 | 整体 `PASS`。 |
| T-09 | 一项阻断发现。 | 整体 `FAIL` 并有修复交接。 |
| T-10 | 未完成、冲突或无效任务。 | 整体 `NEEDS_HUMAN`。 |
| T-11 | 31 项模拟任务。 | 峰值并发不超过 30 和系统 cap。 |
| T-12 | 任务记录出现 Terra/Sol。 | 校验失败。 |
| T-13 | 错误重绘图与原决策树无关且文字相撞。 | 同时报 `semantic_mismatch` 与 `layout_collision`。 |
| T-14 | 原图/独立汉化图配对正确。 | 无语义错配。 |
| T-15 | 输入目录哈希快照前后比较。 | 插件未改动输入。 |

## 3. 公开 fixture 规则

- 使用手工重绘、自有或明确可再发布资产。
- 不使用本对话附件、课题组报告截图或有不明授权的论文 Figure。
- 每个 fixture 有来源、许可、预期发现与断言。
- “图片打架”fixture 使用自绘中文决策树、无关柱状图和故意的文本碰撞；它是产品的关键回归案例。

## 4. 发布验收

1. 运行全部自动测试与插件 manifest 校验。
2. 运行公开 fixture 端到端生成账本。
3. 使用至少两项公开 fixture 进行真实 Luna 烟雾测试，确认一图位一代理、模型锁定和结构化返回。
4. 主代理审阅 Luna 结论并修正产品中的提示、Schema 或资产问题。
5. 渲染并人工审阅 README 的全部图，确认无裁断、无错配、无文本碰撞、无敏感路径。
